# Codex 桌面兼容边界

Last updated: 2026-10-22
Status: active
Owner: backend

## 目标

网页使用本地 Codex 的线程与项目身份，侧栏和聊天读取同一份官方数据。新增兼容逻辑按元数据、历史读取、执行协议和展示职责拆分，避免继续向主会话类堆入解析代码。

Codex 当前主链路以 [V2 聊天契约](../refactoring/codex-chat-v2.md) 为准；旧 snapshot/canonical/SSE 规划仅作历史参考。

## 组件

- `CodexSidebarService` 只读探测 SQLite 列和桌面全局状态，`codexDesktopSidebar` 负责项目身份、显式成员关系、置顶和顺序。HTTP 列表通过 `sidebar-read-runtime` 异步读取；数据库及 WAL、全局状态各自按文件身份、体积与纳秒时间失效，稳定版本才缓存，进行中的同源读取合并。业务快照只由 Service 持有，实时 live/activity 每次重新装饰；同步兼容入口不属于此次 HTTP 优化范围。分组 ID 不能由显示名称或路径替代，同路径项目允许拥有不同身份。
- `CodexHistoryReader` 通过 `thread/read`、`thread/turns/list` 和 `thread/items/list` 分页读取 typed 历史，不为查看调用 resume。旧文件历史在入口复用 `HistoricalSessionService`；Codex V2 不经过旧 `appServerHistory` 的全量投影链。
- `CodexRequestStore` 持久化独立请求回执，官方历史仍是完整对话来源。`CodexThreadService` 串行派发 queue、校验 steer 目标和 interrupt 归属，并以稳定 threadId 发布 WebSocket 增量；未知接收结果只核对，不自动重发。
- `CodexDesktopClient` 连接同用户私有 Unix socket，发现线程 owner、提交原生异步问题回答、携带设置启动新轮并定向停止当前轮；不暴露通用 IPC 调用。`DesktopQuestionResponder` 校验官方问题、未回答状态和幂等身份，`DesktopQuestionRecovery` 分页核对丢失确认的回答。回答、停止与普通引导的能力独立，不据此开放桌面审批。
- `CodexTurnController` 独占停止分流：网页持有轮次调用 app-server，桌面轮次先只读核对最新轮与 owner，再调用原生 v4 定向中断。请求携带用户看到的 `expectedTurnId`，重复在途请求合并，已结束或已换轮不停止后继轮，确认丢失只刷新状态。metadata 的 `desktopInterrupt` 与引导能力分开，桌面发现暂时失败时前端以有界间隔重读恢复。停止只针对当前轮，不保证持续目标一并暂停。
- `appServerModelCatalog` 获取当前 app-server 的实际模型和推理档位，缓存并合并并发请求。配置中的未知模型不应被赋予虚构能力。
- `CodexThreadStateStore` 与 `permissionPolicy` 还原当前线程设置。兼容旧沙箱、managed 文件系统和 disabled 沙箱存储；无法安全表达的自定义策略必须先明确保存权限，不能静默扩大。
- `imageAttachments` 管理受验证的持久图片引用。上传只接受 PNG、JPEG、WebP、GIF，输入仅携带服务端附件 ID。任意客户端文件路径不得直接变成模型输入。
- 预上传与发送复用同一图片上传Promise；上传状态替换附件对象后，每个等待者的发送快照仍需同步同一uploadedId。上传失败保留草稿与原File，重试由用户触发；离开会话后不发送旧提交或覆盖新草稿。
- `sidebarResponse` 负责侧栏表示、br/gzip/identity 协商和 ETag，鉴权后读取最新数据。`sidebarProgressiveFrames` 固定同一快照的首批与完整帧，`sidebarProgressiveTransfer` 独占流反压和关闭生命周期。Brotli 使用内置文本模式quality5，gzip参数保持。304不能绕过鉴权或编码拒绝；每runtime只缓存最近完整JSON响应及按需两种编码的结果/进行中Promise，压缩失败清除所属失败项并保留错误，允许下次重试。
- 前端 `codex-chat-store` 保存每线程一份 turn/item 状态；`codex-chat-runtime` 装配 HTTP 提交和补读生命周期，`codex-connection` 独占握手期限、重连及前台恢复。首次 WebSocket epoch 只建立基线，保留在途首读；已知 epoch 改变仍废弃旧读，逐字段 revision 继续保护新事件。`codex-read-refresh` 负责 metadata、最新 turns、回执列表与合并刷新；单次调用最多等待两批读取，后续通知由单一后台读取追赶，持续执行不能无限延长初始化。`codex-history-items` 统一 items 首读、cursor、after 和同轮进行中读取合并，显式请求既有上限 30 条。
- `codex-item-hydration` 独占可见/展开归属及双槽页调度，每页释放槽位，显式展开可提前取得空槽。实际 FIFO 队首最多被优先页绕过两次，随后按年龄服务，保护最新轮和普通轮；这是可用槽位的 grant 边界，不是远程请求挂起时的墙钟保证。完整终态旧轮复用、最新轮 after 续读、cursor、权威详情和卸载清理保持，过程默认折叠，正文不裁剪。
- 历史轮询以 `turn.metadata` 只修正已加载轮次，避免把未知上一轮追加到最新轮之后；原生事件仍使用 `turn.upsert`。结束收尾保留旧轮相关性直到 tail 增量和末条详情完成。`codex-chat-item-order` 归并完整分页锚点和稀疏摘要，摘要临时追加的位置不作为完整历史顺序；最新窗口、向前游标和追新 tail 独立维护。
- `codex-subagent-activity` 按同轮明确 startedItemId 投影子任务完成状态，覆盖窗口外已知完成项及倒序到达，隔离不同唤醒；同 item 的终态活动不被旧摘要重新打开。展示缓存将投影活动纳入失效判断，不修改原生完成事件或窗口顺序。
- `readJsonTransfer` 只在 V2 turns/items/单条详情成功 GET 完成原 JSON 序列化后协商 gzip level 1；保留鉴权、安全头和 no-store，不保存历史正文缓存或 ETag。允许 identity 时，8 KiB 以下保持原文；不允许 identity 时，小正文也可 gzip。每 runtime 最多两条活动压缩管线，没有待压正文队列；满额按协商返回完整原文或明确的可重试 503。
- 每个线程 context 独立持有展示适配和轮次模型 factory，未变的历史 turn/item 复用引用，时间线直接消费父级已生成的模型。缓存不回写 store，嵌套正文与 presentation 更新沿用 upsert 替换对象的约定；模型选项改变时重新派生。
- 草稿编辑继续推进异步对账 revision，但不推进历史 `presentationRevision`，因此纯输入不重跑历史投影。内容、排序、回执、轮次和直接详情字段的响应式依赖继续生效。
- `thread-item-markdown` 持有每个渲染组件的 Markdown 与高亮实例，组件保留真实 DOMPurify 清洗和图片/链接事件。独立正文和 process 语言字符串 computed 避免同文兄弟对象更新时重复解析或清洗；fence 缓存按完整源码和语言匹配，最多 8 项、保留字符串预算 256 KiB，超预算仍完整渲染，失败不缓存，item 身份变化和卸载清空。cwd 变化继续更新链接，权威正文替换仍重新渲染。
- `message-stream-scroll` 持有贴底、阅读意图与滚动任务归属；ChatView 保留 DOM、布局、viewport、observer 和事件装配。显式展开过程立即暂停自动贴底，内容补齐、流式增长和已排队强制回调不能夺走位置。真实回底输入恢复跟随；连续惯性按有效位移、方向、尺寸和活动间隔续期，同一次有效触摸可反向。无手势布局、静止事件和过期链不能解除阅读保护，切换上下文或卸载使旧任务失效。
- `app-viewport` 统一测量可视高度、顶部偏移和底部空隙，App 薄装配发布共享 CSS 变量；Chat 复用纯测量，保留自身输入尺寸与跟随。小数不独立取整，零值不发布零高度，卸载移除监听并恢复原样式。App 布局链约束在有限视口，document 不承担业务内容滚动；列表、消息、短屏登录与预览各有可达的内部滚动区域。
- 输入宿主不参与 flex 收缩，按自然高度和聊天区 70% 上限占位，超限内容在宿主内部滚动；消息区接收剩余高度。原生弹层和窄屏预览使用同源可视高度及顶底偏移，长预览错误在消息层滚动并安全对齐，不能覆盖关闭头部或裁掉重试。
- Markdown 保留语义表格标签，以有名称、可聚焦的局部容器承接宽表格横滚，不改变全局宽度。原始 HTML 仍关闭，DOMPurify 不许可通用 style、事件或危险 URL；process 独立名单、原缓存和图片/链接策略不变。
- 旧 CC 的 session/PTY/终端 WebSocket 路径独立保留，不迁入 Codex 的 typed 协议。
- 旧会话实现位于 `sessions/conversation/`：`legacyThreadProjection` 负责 thread snapshot、raw/canonical 入口和历史对账；`legacyConversationRuntime` 负责兼容 conversation state、delta 和广播；`legacyConversationTurns` 负责 turn 创建、身份 alias 与终态。`SessionManager` 保留同名显式委托和生命周期装配，所有模块共享 session 上的原状态，跨职责操作通过 `manager` 方法动态调用，continuation 复用投影 helper。

## 不变量

1. 每次提交有独立请求 ID，文本空白和图片引用必须保留。queue 启动下一轮，steer 可向同一活动 turn 添加独立 user item；不能假设一条请求必定对应一个新 turn。
2. 增量逐字追加，完整消息按消息 ID 替换；不同官方 ID 的同文内容仍是独立条目。
3. GET 历史只读，不恢复执行，不持久化完整对话投影。分页缺项代表尚未加载；有界预览、详情与图片媒体读取各有明确边界。
4. 官方历史是持久正文来源，实时事件更新相同 item ID。旧页或迟到事件不得覆盖较新的完成内容；官方完整详情可以补齐预览。
5. 迟到的 A 会话请求不得覆盖 B。订阅按稳定 threadId 和 epoch/seq 恢复，缺口补读历史；服务重启后的未决请求自动核对，不重发提示词。
6. 公网 HTTP 和 WebSocket 使用浏览器当前 origin，不能泄漏或连接服务器的本地监听地址。
7. 本地图片代理要求认证，返回 sandbox CSP，防止 SVG 作为同源可执行文档打开。

## 旧 CC 兼容设置

CC 的显示名称保留在网页会话元数据及自定义名称存储中，provider 不再自动生成 `--name` 参数；真实 create 与命令展示使用同一参数合同。用户显式配置的 `CC_EXTRA_ARGS` 仍按原值传递，`--resume`、模型与权限参数不因此改变。

`threadComposerState` 先解析 canonical provider。只有 Codex 读取桌面默认值、线程状态和模型能力；CC 使用自身 provider 的默认模型，未配置时保留空字符串，由 CLI 决定。有效 live 设置和调用方显式覆盖继续优先，恢复前的设置读取仍可用 `git=0` 跳过 Git。

共享 composer 的 reset、snapshot 和历史设置应用遵守同一 provider 归属，明确的空模型与缺失字段不同。晚到的 Codex 配置不能填入当前 CC 的空模型；原认证代次、设置对象身份及用户模型/附件保护继续生效。该合同覆盖新 live、历史重开和发送时冷恢复，不扩展 CC 的终端协议。

## 访问与初始化

App 在身份检查期间预取当前路由的静态视图，初始路由未解析时等待路由就绪。列表与登录只加载自身，明确 Codex 历史加载 CodexThreadView，其他聊天先加载两条路径共用的 ChatView；未知 live provider 仍由原认证后流程识别。预取不挂载、不读取业务数据、不修改身份或发送屏障。

`async-view` 的公开 preload 与真实挂载共用代码加载 Promise，失败保留给当前消费者。当前视图的代码或共享样式仍在下载时立即显示加载状态；业务 API 已完成也不提前移除，成功后由真实视图替换，失败沿用错误恢复入口。路由切换或卸载即移除旧状态。Codex 视图通过显式 `dependsOn: [ChatView]` 共享完整依赖结果；依赖先登记，自身 import 同时推进，聚合只约束就绪，不串行下载。私有 WeakMap 保存本工厂的 loader，不复制 Vite 的 CSS seen 状态，也不按文件名解析依赖。新增静态共享依赖时须同步声明并验证，避免后续 importer 跳过失败或仍在下载的共用样式。

后台预取失败不重载；当前挂载的消费者还须匹配即时路由、身份与原代次，才能对 JS/CSS 旧资源执行现有 30 秒窗口内单次自动重载。离开页面或身份变化后的旧结果不能刷新新页面。普通错误、存储不可用或窗口内再次失败保留错误通道，并显示可访问的失败提示与“重新加载”命令；无关列表和登录不继承聊天依赖的失败。

构建阶段为较大的 JS/CSS 生成 gzip/br 侧文件，先写临时文件再原子替换。`frontendTransfer` 仅为实际 dist/assets 下的内容指纹资源提供编码协商、长期不可变缓存、ETag、条件请求与 HEAD；源文件更新使旧压缩侧文件失效，没有压缩体的旧构建继续使用原文。HTML、无指纹文件、vendor 和认证后的本地图片仍为 no-store。缺失 API/资产返回 404，不能被 SPA HTML 回退替代。

历史 JSON 传输用标准 Node 流反压，按块编码且不拆开 UTF-16 surrogate pair，支持合法大于 4 MiB 的正文。取消或失败销毁管线并幂等释放容量；gzip 头发出后的故障终止响应，不能拼接原文或把截断当完整 JSON。该机制约束新增传输缓冲，原完整 JSON 字符串的序列化与内存成本仍存在。慢接收端主动断开时，socket error 可先于 response close 经 Koa 记录 EPIPE/ECONNRESET；记录时 res.destroyed 仍可为 false，随后管线、活动句柄和容量正常回收。开放响应的真实压缩错误仍须可观测，不能仅按错误码屏蔽。已销毁流对象内部保留的 Node pipeline 监听不等于存活响应或资源泄漏。

身份确认后即可显示页面和开始读取 Codex 历史，模型目录后台补齐。共享配置读取属于当前 App 认证代次，合并并发、成功保留 60 秒、失败可重试，身份失效时清除；显式重试可强制刷新。旧 CC 入口继续等待配置。V2 发送仍需完成线程设置读取、至少一次有效的服务器回执列表核对和设置保存屏障；首次回执失败或结构无效时保持锁定，成功重试后恢复。目录迟到只更新可选模型，不能覆盖线程设置、用户选择或附件。设置通过 `?git=0` 读取和保存，Git 在当前上下文后台查询；旧服务仍返回 Git 时直接复用。分组新建线程不携带占位或缓存的默认设置，交由服务端读取实时桌面默认；旧会话无线程身份的升级路径保留该会话已有的模型、思考强度和权限选择，外部 API 的明确设置覆盖也保留。

`api-read-deadline` 为认证检查、`/api/config` 和线程 composer-state 的 GET 提供单次 15 秒总期限。精确 `/api/sessions` 和 `/api/session-catalog` GET 采用 30 秒连续无进展期限及 120 秒绝对上限：收到有效响应头或非空正文数据重置停滞计时，不能因总时长超过 15 秒就中断仍在传输的目录。`api-read-json` 通过标准 reader 和 UTF-8 decoder 为普通 JSON 记录实际字节进展；NDJSON 由原 decoder 记录。查询参数不改变归属，原有一次保存凭据恢复及重读共用初次请求的绝对预算。超时以 `READ_TIMEOUT` 走现有错误/重试入口；取消或超时后的旧结果不能发认证失效通知或继续重读。私有 signal 在结算后结束仍未消费的所属响应，清除所有 timer 和外部取消监听；不会取消调用方 signal。其他 GET、显式登录和业务写入保持各自原生命周期。

认证检查超时结束启动等待，显示登录入口与读取错误，保留保存的凭据和记住偏好，不再立即追加一次自动登录。其余正常认证失败/自动恢复行为与身份代次保护保留；该边界不代表显式登录、其他写入或全站所有网络请求都有同一超时策略。

设置控制器的 `readComposerStateForThread` 区分 applied/preserved/stale/failed，并携带该次服务器快照；旧布尔读取接口保留兼容。V2 初始化和重试仅以当前有效快照建立首次基线，期间用户修改不被吸收为初始值，旧读取不能清新失败或解锁发送。PATCH 失败与读取失败各自受代次保护。

`codex-read-requests` 管理聊天读取的 deadline 和关闭取消。离开线程时取消自身在途 GET、清理计时器并释放排队等待；提交、引导和停止等已发 mutation 继续结算，不因页面关闭中断模型或重发。旧附件上传不再回写已销毁 context；旧发送回执只定向合并到最新持久化记录，保留新草稿、图片和其他请求，重复 dispose 不再次保存旧稿。

服务端 `historyReadContext` 为鉴权后的 metadata/turns/items/detail/image GET 独立持有响应关闭信号；正常 request close 或成功 response finish 不取消，finally 移除本次监听。reader 在共享初始化等待、metadata、分页、两阶段详情、兼容读取、presentation/媒体返回和路由对账/JSON 边界检查归属；离开的等待可结束，但共享初始化、其他客户端和后台回执恢复继续。迟到结果不入缓存或触发后续读取，已开始的同步 I/O/CPU 无法追溯抢占。

`appServerRequest` 持有单 RPC 的 pending/deadline/首次结算清理，bridge 保留原 Map、全局 ID、连接和进程生命周期。第三参数中的 signal 是本地选项，reader 只对三个历史 RPC 传入，不进入 wire 或线程状态；未绑定信号的写调用保持原 uncertain 和回执核对语义。取消只释放单 ID 的本地等待及计时器/监听，晚回复按未知 ID 忽略；不发送猜测的远端取消、turn/interrupt 或关闭共享 WS。安装版本0.156.1的实验协议导出未声明通用历史RPC取消，不能据本地清理声称远端工作停止。

`metadataReads` 仅合并同线程进行中的元信息读取。显式 `getThread` 不直接复用暖值，`threadMetadata` 保留 2 秒、64 线程值缓存；分页和正文不进入此协调器。底层 RPC 的 signal 属于共享 entry，各 HTTP 调用者独立退出，无 signal 的后台调用也计入存活 waiter；最后 waiter 离开才取消本地 owner。失败可重试，发布与清理校验 entry 身份。外部 `remember` 使旧 entry 失去发布权，既有 waiter 仍获得自身响应，不能覆盖较新缓存或删除后续 entry；不保留长期线程代次 Map。

metadata 与 turns 各自保留读取失败和代次，汇总为 `historyReadError`；回执列表失败独立。稳定回执或其他成功动作不能隐藏历史失败，原轮询退避继续安排恢复，成功返回有效的对应数据后才清错。坏 200 响应不能确认空历史或解锁首次发送。`codex-runtime-errors` 为固定十类动作保存有界失败归属、代次和必要目标 ID，向既有 `state.error` 投影当前失败；成功只清除自身仍有效的错误，旧成功不清新失败，也不重放 mutation。

会话首屏由最新历史页决定就绪：`initialHistoryTurnId` 记录首次最新轮，在该轮最新正文窗口完成前，时间线保持隐藏并显示加载或读取失败状态。本地恢复、HTTP 回执和 WebSocket 先到的消息不能提前打开时间线。该目标轮在未完成时保持自动读取资格，即使更新的实时轮已经到达、隐藏的时间线尚未触发可见性观察。首次读取重试可更新目标轮；窗口完成或明确空历史后，后续刷新、新轮和向前分页不再关闭时间线。回执及其恢复操作仍保留。

读取恢复的唯一手动入口位于输入区可见状态旁，历史顶部只保留分页。`canRetryReads` 仅跟随历史、回执列表、设置和目录错误，普通恢复/引导/停止错误不单独显示连接重试。现有 context 的 `actions.reload` 同步抑制重复点击，忙碌状态等全部读取收尾；目录与历史并行，设置在历史刷新后推进，不等慢目录。目录也持有 context 内读取代次，旧目录成功不能清新失败或覆盖新模型；跨线程旧结果与 busy 不作用于新草稿。

`CodexSubmissionFeedback` 在输入区呈现本地提交进度、当前提交失败和真正阻塞发送的 unknown；只引用同一回执，不复制原消息/附件或新增 turn。context 仅记录本地 submit 返回的 ID，展示每次回查 store；不能以 localOnly、列表尾项或旧错误推断本次归属。其他来源或重开后的阻塞 unknown 使用中性状态说明，优先于本地旧失败。读取错误和连接重试继续各自归属，反馈出现或结算不触发焦点、滚动或自动发送。

输入区与时间线复用原 ID 的恢复和核对动作及共享 busy。明确缺失仍须再次读取取得新 404 才能人工解除；其他 unknown 只能只读核对。解除仅改变本地发送门禁，保持不确定性与重复风险提示；官方更新仍决定最终状态。成功恢复清除当前本地失败提示，现有新草稿防覆盖、原图片/设置恢复及同 ID 对账保持。

反馈标签和动作位于紧凑头行，完整错误详情使用有名称、可聚焦、最高90px的原生纵向滚动区域，保留换行及长词折行；不截断正文，不把长错误转成全局滚动。极短屏继续由原输入宿主内部承接超限内容。同一回执由输入区播报时，其可见时间线footer关闭live播报，其余回执保持原状态语义和操作。

引导与发送共用严格的“已确认缺失且人工解除”判定：仅 unknown、`confirmationDismissed=true` 且 `receipt_not_found` 的本地记录可不再阻塞。服务器重新出现回执后合并会清除本地解除标记，真正未知的记录仍保持核对门禁；动作继续使用原请求 ID。

本地乐观回执用内部 `localOnly` 标记区分来源，服务器确认不受客户端时钟影响；相同服务器来源内保留时间和终态保护。5xx/408 表示结果尚待核对，按原 ID 获取实际回执；补查失败不把已确认执行降级成 unknown。原本未知且明确缺失的回执保留既有人工解锁流程，不能据一次读取失败允许重复执行。

`GET /api/sessions?compact=1` 可返回 `sidebarFormat=compact-v1`：完整记录只在顶层 sessions 保存一次，项目分组按有序 sessionIds 引用。客户端在刷新入口完整还原后更新既有状态；组成员、顺序及元数据不变。缺少 canonical 记录或同 ID 内容冲突时服务端保留旧表示；客户端收到未知格式或坏引用明确失败并保留上一份有效列表。默认 API 形状、认证和 private/no-cache 策略不变，ETag 按最终表示计算。

侧栏编码沿用当前Koa的接受器解析质量值、通配和拒绝；为使常见浏览器同权重请求实际选择br，只对独立接受器的编码项做小写及稳定优先排序，不改原请求或手写质量解析。质量和显式项specificity仍优先。该局部适配复用当前Koa accept实例的构造类型，升级Koa/accepts时需重跑协商回归。无头返回原文，全部禁止时返回406/no-store且无成功ETag或编码头；合法跨编码请求共享完整JSON的弱ETag和Vary，304在实际压缩前结束。不会裁掉用于列表搜索的inputPreview，也不改变活动变化导致的合法失效。

冷目录可精确选择 `GET /api/sessions?compact=1&progressive=1`。合法 canonical 快照返回 `application/x-ndjson`、private/no-store 与恰好两个 JSON 行：协议 `session-sidebar-progressive-v1`，首帧 `type=bootstrap, complete=false`，尾帧 `type=complete, complete=true`；两帧共享完整 compact JSON 加换行的 SHA256 base64url snapshotId，亦为原弱 ETag 的内容身份。首批包含每组前5及最近活动前20身份的记录并集，保留所有组元数据、成员顺序与完整预览，counts 独立保存全量会话、活动、运行数及各组总数/运行数。完整帧与原完整 compact 表示等价。两行在首次异步等待前固定，不在首批后重查另一份快照。重复参数、未选择、小目录、降级或无法无损证明身份/覆盖关系时继续返回原完整 JSON。

渐进传输用标准 Node 编码流，首行 flush 后才传尾行；尾行以16 KiB分块等待 write 回调承接下游反压，不设置 Content-Length。每 runtime 最多两条活动流，没有待压正文队列，满额回退完整 JSON。取消/finish/close 幂等销毁自身编码与输出并释放容量和监听；头前错误保留安全头/no-store，头后错误可观察并断开响应，禁止拼接降级正文。完整 JSON 缓存与现有协商/认证/406/304边界保持。

`session-sidebar-stream` 仅消费成功 sessions GET 的渐进表示，标准 reader 与 fatal UTF-8 decoder 检查协议、帧顺序、同快照身份、引用、计数及首尾记录/组连续性。首帧可同步发布；只有完整尾帧和正常 EOF 均通过才返回成功。截断、额外帧、错版本和坏引用明确失败，JSON fallback 保留。整个鉴权恢复、响应头、两帧及 EOF 共用目录读取的 120 秒绝对上限，非空字节只刷新 30 秒停滞计时；首批不重开总预算。结算清理 reader、lock 和取消监听。产品只显示单次中文未完整提示，原始解析/传输原因保留在 cause 与错误码中。

登录端点的 401 由登录流程处理，不进入通用请求的自动恢复或身份过期通知。自动登录只有明确认证拒绝才清除保存的 token；网络、限流或服务错误保留其值。显式登录/退出开始时推进请求认证代次，旧请求及其凭据恢复的迟到 401 不能影响新登录，包括旧历史和流式请求。启动、登录、配置和列表的迟到响应不能恢复已失效的身份。

## Codex 用户交互

`AppServerInbound` 独占服务端主动请求，保留 typed RPC id、原 socket 与连接代次；数字和字符串身份不合并，同 item 的多个 approvalId 独立。旧 socket 的消息与关闭不能作用于新连接。`CodexInteractionService` 在独立内存 registry 保存回调，通过 V2 `interactions` 的 list/detail GET 与 `/:id/respond` POST 提供权威快照和回答，沿原认证/跨源/正文限制。它与网页主动发送的持久 `requests` journal 分离，答案、秘密字段和 proof 不进入日志、事件、磁盘或聊天草稿。

| 交互 | 支持范围 |
| --- | --- |
| 用户提问 | 多题、选项、自由输入、其他答案、secret、逐题/全部跳过；isBlocking 真实保留，不用弃用倒计时自动回答 |
| 命令/终端/文件审批 | 本次、会话、拒绝继续/停止及原请求提供的执行/网络规则；显示真实命令、目标、路径和已有修改证据 |
| 额外权限 | 选择原网络/文件权限子集，兼容路径/glob/special/deny；默认turn、session须明确选择，deny不能被移除扩权 |
| MCP 表单 | 标准primitive、required、数值/长度/数量/format、单多选与标题；兼容同结构的openai/form/openaiForm和安全根注解 |
| MCP URL | 安全HTTP(S)链接，明确打开后再确认，打开本身不是授权完成；支持拒绝/取消 |

`availableDecisions` 存在时其中内嵌的 typed 规则本身就是权威原提案，不要求可空 `proposed*` 冗余重复；回答必须精确等于原可选值，不能改写规则。列表不存在时才依据 proposal 构造决定。回答先原子claim，再向原socket至多写一次；同responseId/内容摘要重试只取回执，其他答复冲突。发送callback成功仅submitted，官方 `serverRequest/resolved` 才resolved。未知发送只GET核对，不自动重放；断线/线程关闭/对应turn终态使句柄失效，null-turn独立MCP不随无关turn清理。无人类回答超时；无网页观察者仍保留回调，网页切走不自动批准或中断。

pending最多128、每线程32，终态最多256；展示参数512KiB、回答1MiB、对象深度64，fileChange证据最多32项。超过容量明确拒绝新请求，不静默覆盖已有。只接管本V2已加载或网页持有执行的官方请求，不从历史、桌面等待标记或任意threadId制造响应权；桌面其他连接及尚未关联的独立子线程仍由原端处理。动态工具、外部token刷新、attestation属于宿主能力，不开放浏览器通用RPC；时钟请求可由主机响应。

V2新建/恢复线程仅在线程config启用 `features.default_mode_request_user_input`，本机0.156.1已验证普通Default模式实际提问并继续；保留原reasoning/模型/权限，不修改全局配置。新增 `manual-review` 为read-only/on-request/user，旧三模式不变。SQLite/rollout共同识别受支持的只读策略+on-request；未知或自定义窄权限不被提升，SQLite不含reviewer所以不声称完整恢复任意外部策略。人工模式不写猜测的桌面全局agent-mode，CC/claude/json_exec明确拒绝。仅Codex V2透传四选项，旧组件仍默认三项。

前端独立interaction state/runtime和composer-top面板复用原WS序列门禁、读取期限及单一轮询。registry epoch/revision/version防旧快照复活；初始、重连、前台、缺口和显式核对从服务端恢复，不持久化审批或秘密答案。普通草稿/附件、设置保存、回执初读与unknown发送屏障保持。面板默认两个常用操作、其他决策及证据按需展开，使用可读语义标签；resolved自动撤去，submitted/unknown保留核对。长正文和短屏宿主各自内部滚动，不增加document滚动或抢草稿焦点。

当前不引入Ajv，未知嵌套/ref/pattern等复杂扩展schema明确禁accept，仍可拒绝/取消；设备 `openai/userVerification` 无真实proof能力，也不能用普通按钮假确认。这些边界不等于支持任意扩展表单、设备验证或跨桌面连接审批。

桌面原生异步问题独立按 `agentMessage.delivery=async`、合法 `call_` 身份及 `questions` 结构展示问题卡，支持选项和自由回答，普通问句不按文字猜测转换。历史回答只按官方 `send_user_message_question_reply` 中的精确问题身份关联；回执接收、排队或完成本身不代表已回答。未回答的问题在来源轮结束后仍可回答，是否可提交由当前能力和发送门禁决定。网页拥有的同一活动轮继续通过原立即引导提交，保留普通草稿和图片。

桌面 owner 存在且支持不可信应用输入时，metadata 发布 `capabilities.desktopQuestionAnswers`。网页通过受认证和同源校验的 `POST /api/v2/codex/threads/:threadId/questions/:callId/respond` 提交请求身份、来源轮、问题索引和回答；服务端读取官方原始问题构造原生回答封装，不接受任意 prompt、IPC 方法、目标客户端或权限设置。显式提交才分页核对来源问题之后的全部相关历史，遇到截断的用户消息读取完整详情；历史不完整、已回答或最新轮发生变化均拒绝发送，不以首屏未加载推断未回答。

前端 capabilities 使用独立版本保护，metadata 等待期间的 status/name 更新不能丢弃新的回答能力；旧能力响应和旧连接 epoch 仍不能覆盖新值。已加载未回答桌面问题且能力缺失或不可用时，通过现有调度每 10 秒仅重读 metadata，后台至少间隔 30 秒，回到前台立即检查；空闲能力探测不下载轮次和正文，明确可用或问题已回答即停止。临时初始化、发送门禁和能力不可用统一显示“回答暂不可用”，不再误报必须在桌面作答。服务更新不会替换已打开页面内的脚本，长时间停留的旧页面仍需重新加载一次。

回答沿当前桌面 owner 的本机通道提交：有活动轮时使用 `thread-follower-steer-turn` v1，空闲时使用 `thread-follower-start-turn` v2，并继承原会话设置。问题回答不进入普通跟进队列，不占用输入框草稿，不扩大普通停止/引导能力。该适配基于桌面 26.1013.40934 的原生协议，已验证 macOS 私有 Unix socket；没有有效私有 socket 或 owner 时不提供该能力，不声称 Windows 或其他版本均兼容。桌面升级后需回归协议。

问题级单飞和持久请求指纹防止多标签页重复提交；写入前持久化派发状态，重启不把回答当普通消息派发。断线或确认丢失只核对，不自动重发、不降级到普通队列。恢复器每次最多读取一页轮次和一页消息，跨 tick 保存进度并覆盖后续轮，仅精确官方 clientId 可确认接收。明确失败可回问题卡重试，未知回执沿用发送锁定；失败回答不能恢复为输入框中的原始封装。官方 IPC 没有原子 expectedTurnId 条件，发送前重查仍不能完全消除 owner 切轮竞态，因此以返回的实际 turnId 和官方历史为准。

官方回答结构经校验后以 `questionReplies` 传递给 `ThreadQuestionReply`，在一条用户气泡中展示灰色问题摘要与回答正文；多问题逐项对应，跳过保持明确。正文按纯文本渲染，未确认回执与官方用户消息复用同一展示结构。已回答问题退为普通问题正文，问题卡不重复答案或已回答状态，未答/部分待答的交互能力与发送门禁保持。

过程展开入口只由实际过程条目产生，不依据旧 `itemsPageLoaded` 标志猜测存在执行记录。最新窗口无工具内容或只有输入时不渲染空兜底入口；可见历史窗口仍自动补齐，真实工具详情在展开后读取，更早内容继续由触顶分页获取。

## 工作区执行

`workspace/service` 持有 runtime 唯一的工作区命令执行器和作业队列；`branches`、`changes`、`patches` 分别负责分支、当前差异和历史文本补丁，HTTP 路由只做鉴权、输入和错误适配。工作区兼容包装与侧栏 SQLite 实例复用 `runtime/processes/command` 的执行核心，各自限制并发和队列；工作区错误类、代码和消息保持。七个 I/O helper 返回 Promise，纯 status parser 保持同步。设置 GET/PATCH 默认仍带 Git，可通过 `?git=0` 跳过；恢复创建只依赖设置时也跳过 Git。

命令采用 argv、无 shell、有界输出、C locale 和绝对截止时间。全局子进程及队列有上限，同 canonical 根的检查、写入、刷新在一个串行作业内；普通目录重叠路径与其中的 Git 根在涉及写入时也互斥。仅合并同参数、同代次的进行中只读请求，不持久缓存结果。分支读取并行，差异每批最多读取两个文件，保留原顺序。只有明确的 not-a-git-repository 可判为普通目录，配置、超时、信号和输出溢出不得变成空列表或干净状态。

Git 当前差异和选中还原使用 canonical 仓库根，返回 cwd、文件路径和 diff header 保持同一基准。历史补丁独立按调用 cwd 校验并映射到仓库子目录；普通目录仍以调用 cwd 为边界。完整文本、链接和路径校验保留，未知写结果不能进入 fallback 或自动重试。

真实文件路径采用 literal pathspec，首尾空格属于文件身份，不能在选择或合成补丁时裁剪。正文末行空格和换行保留；JS 文本执行先校验并准备整批内容，再进入一次受跟踪的写入，零上下文 hunk 同时累计前段的行数变化与实际匹配漂移。普通 patch 工具无法可靠表达空白/引号文件名时，在任何写入前选择已有 JS 执行路径。

错误区分 `not-applied`、`applied`、`unknown`，并携带 code；dirty 为 409、超时为 504、队列或关闭为 503、写已完成后刷新失败为 502。前端保留已执行结果并禁重复写，只读刷新不会阻塞设置保存或聊天。Git 读取失败保留当前 cwd 和错误，显式刷新可恢复；历史补丁结果不确定时持续禁用补丁操作并提示，需核对文件后重新打开会话，不能推测撤销方向。文件面板区分工作区身份和读取代次，同目录新增历史文件不丢弃正在结算的写入。

Git 写开始和结算会使旧读取失效；设置响应、目录 watcher 等自动读取不能解除写入后的待确认门禁。显式刷新须在失败后重新发起并成功返回，成功写入后的确认也不能合并复用写前快照。同线程晚到的 cwd 元数据不会遗留 busy，写结算后保留显式确认要求；旧线程结算不清除新线程的读取或写入状态。实时文件面板使用该次响应的 canonical cwd，历史文件继续使用其调用 cwd，预览与补丁保持一致。

退出流程立即关闭工作区和侧栏读取队列及其他运行资源，等待子进程和锁确认释放；侧栏关闭同时等待文件读取，终止后的结果不得发布或确认空目录。3 秒连接兜底终止未响应的 WS/HTTP，不代替资源关闭确认。health 暴露工作区命令和作业统计；侧栏查询、缓存命中和队列统计供内部验证使用。

## 执行归属边界

同一线程只允许一个运行时直接写入。网页发送遇到官方 writer 冲突时，可通过 Codex 的持久消息队列向原端排队，保存请求原文、附件及官方队列 ID；不杀桌面进程、删锁或静默 fork。队列保存成功仅代表待执行，未加载、中断或持续目标状态可能延迟消费；历史 userMessage 的 clientId 和完成 turn 才能确认执行结果。

队列请求只能继承桌面会话当前设置。网页本次发送携带任何模型、推理或权限覆盖值时拒绝转入桌面队列，不暗中放宽权限。已确认排队的消息可调用官方 `thread/queue/delete` 撤回；若原端已领取，保留待核对状态，不能报告撤回成功。

`desktopQueueSync` 在订阅轮询、请求列表读取、后台恢复和 `thread/queue/changed` 时核对官方队列，同线程合并读取，单次最多3秒且不阻塞历史首屏。请求100项并要求单页完整返回；不拼接变化中的 OFFSET 分页来推断缺失。失败、部分数据、重复身份及过期回执均不能移除卡片。桌面删除与消费都可能使消息离队，因此新增 `removed` 只表示官方队列已不存在该项：移出待处理集合和网页队列，不冒称撤回或中断、不自动重发。回执保留在持久日志，刷新和重连不会复活；后续精确官方 clientId 与 turn/item 证据仍可恢复真实执行状态。

立即引导和停止只针对网页已知且持有的活动轮。桌面队列的回合不得由网页标为可引导或可中断。网页独占线程的成功验收不能替代桌面队列验收。

队列行同时保留引导与撤回入口。网页持有活动轮的 `received` 消息可引导；桌面已入队消息的引导按钮禁用，并通过说明标注需在 Codex 桌面端操作。独立 app-server 不具备桌面 owner 的普通引导能力；新增本机适配仅用于经过官方问题校验的异步回答，不接受普通队列引导。`thread/queue/start` 是启动新轮，不能冒充引导，也不能先删除队列再尝试发送。

普通跟进的默认发送方式读取桌面 `desktop.followUpQueueMode`，`interrupt` 兼容归一为 `steer`。已就绪桥接优先按会话目录读取有效配置，限定3秒并按连接代次与目录单飞缓存5秒；不可用时读本地配置及桌面初始缓存，最终使用官方默认 `steer`，只向网页返回模式字段。会话设置优先于全局配置，回前台和重试重新读取，旧响应不得覆盖更新值。按钮和Enter遵循配置，发送方式菜单允许显式覆盖；无桌面owner即时引导能力时保留草稿并提示，不静默改为排队。问题回答通过原活动轮引导或受限桌面回答通道处理，不受普通跟进的排队配置影响。

输入区主按钮在运行中且无有效文字、无附件时显示停止方块；有文字或附件时显示发送箭头，默认发送模式仍读取客户端配置。附件上传中或失败时保留发送分支，是否允许提交由原发送门禁决定，不能将“暂时不能发送”误判为停止。清空输入后恢复停止，空输入的Enter不触发中断。停止只对网页持有的活动任务启用，桌面其他连接的任务显示禁用停止及对应说明；停止中的重复点击受保护。

排队跟进在提交时记录本地 `initialPlacement`，从 `sending/received/dispatching/queued` 始终留在输入框正上方；普通空闲新任务及立即引导仍按原聊天流程显示。桌面仍持有 writer 时，即使任务空闲，传递消息也可能经过官方内部队列；该 `queued` 回执不能把已明确放在正文的空闲消息移到排队区，交接期间显示“发送中”。位置选择在刷新和回执合并后保持，其他端同步且没有本地位置的排队回执继续按原状态展示。位置、已确认执行和已恢复草稿标记只保存在本地回执，不发送给后端。官方用户消息、clientId或含执行轮次的执行状态确认消费后才移入正文，历史窗口外的旧官方输入也不得被滞后回执重新插入。

当前活动轮只由已加载的最新轮判断，不能从更早历史里挑出遗留的运行状态。最新轮已完成时，旧运行轮及其回执不得让新发送误进排队区；新 accepted/running 回执的目标轮尚未到达页面时，仍保留它作为活动证据，不以尚未加载推断完成。

待发送区采用贴合输入框上沿的单行窄条，支持图片缩略图、点击展开完整文本和引导/撤回操作。未执行消息确认撤回后只移除队列行，保留内部回执，不能构造“已中断”聊天轮。排队失败或结果未知仍在原卡片内保留唯一反馈与核对/恢复入口；恢复不得覆盖已有草稿，成功后移除失败卡片。可撤回的桌面队列使用原官方接口，网页持有活动轮的待发送消息可显式引导；不确定结果不能自动重发或假称撤回成功。

排队标记、撤回和引导图标使用Lucide 0.543.0的 `list-end`、`trash-2` 和 `corner-up-right` 原始路径，由共享 `LucideIcon` 组件渲染，统一18px显示和原生2px线宽。仅打包这三个图标，不增加运行时依赖；完整ISC/MIT声明随静态资源发布于 `/licenses/lucide.txt`。

桌面 owner 的 item delta 仅发给其连接，另一个 app-server 的只读历史不会提供单条消息内部的 token 流。网页对已关联的桌面 turn 增量读取已持久化 item，并按官方 item ID 展示新说明消息和工具过程；回复 item 结束后以完整历史校准。不能把跨进程视角中无完成时间的 `interrupted` 当成真实终态，也不能将完成后打字动画称为实时流式输出。


## 维护

`CODEX_BIN` 应指向与所读取桌面数据相兼容的官方 CLI。协议和内部存储格式不同，不能只根据公开 RPC schema 假设 SQLite 沙箱 JSON 的形态。升级后应使用隔离会话实测三种权限的保存、执行和重开。

具体回归范围见 [回归计划](../testing/regression-plan.md)。旧文件归档和删除接口尚不适配新版桌面线程管理，不能用于宣称网页具备完整归档同步能力。

## 会话列表与运行状态

网页默认使用 `/api/session-catalog` 的按需目录，旧 `/api/sessions` 完整与渐进表示继续兼容。`sessionCatalogPages` 保存最多4份、最长120秒的快照，仅持轻量记录和完整搜索索引；初始按桌面分组顺序从未折叠组每组最多5条、总计最多20条，最近活动视图每页20条。完整预览和模型设置不进入目录记录；服务端按完整标题、预览、项目、路径与身份做NFKC、多词AND搜索，返回真实总数。分组元数据与计数保留，游标经HMAC绑定视图、查询、组、页大小、快照与位置，不能跨版本拼页；快照失效409由客户端按已取范围刷新后恢复。`loaded`只能为非负安全整数，实际读取按快照实有数量钳制，不以固定累计条数阻止合法的大目录继续分页。

`paged-session-catalog` 独立维护当前查询及请求代次。列表只在近视口且已展开时读取未加载组，用户向下滚动到当前页末尾时自动请求20条，保留手动加载和失败重试；首次相交不自动耗尽目录，游标按组去重，在途单飞。忙期间的有效触底意图恢复后执行一次，失败或查询变化清除待执行意图。搜索250ms防抖，在防抖期离开并返回会对齐保留的查询。初始空活动列表的后续刷新仍请求至少20条，以便发现新会话。每15秒只刷新当前已加载范围，隐藏页面零轮询，回到可见立即单飞同步；离开取消所属在途分页，保留可用目录和返回位置，认证变化清空。页数据就绪不把 `sessionListComplete` 标为完整旧目录，展示通过独立 `pagination` 状态判断；分组新增依赖其真实cwd，不等待所有历史记录。样式置于独立列表样式表，原视图风格保留。

`element-visibility` 封装IntersectionObserver及240px预读范围，卸载断开并阻止迟到回调；不可用时立即读取，避免缺失内容。进入会话先读取最新1轮及末尾30条，等待最新窗口期间不展示稀疏旧摘要，定位使用instant直接到底。`itemsWindowIds`是渲染窗口的成员集合，摘要刷新不扩大窗口；实际最新页、更早页与实时WS更新按官方身份合并。HTTP仅items分页支持单个`sortDirection=desc`，返回页内仍按时间正序显示。后续新内容从独立latest尾锚按`after`升序分页补齐，不漏掉两次同步之间跨页的记录。

`codex-history-items` 分别持有latest、earlier与兼容完整过程读取。`applyLatestItemsPage`维护增量尾锚，`applyEarlierItemsPage`维护向旧内容分页的游标；两者不能混用，迟到页受epoch与逐项revision保护。`codex-history-window`在触顶时先读取最早已加载轮次的更早30条，耗尽本轮后才读取上一轮1条及其尾窗；每个用户意图仅补一页，错误保留原游标供重试。完整输入、Steer和正文保留，展开过程只展示当前窗口并按需补单项详情。两条自动读取槽、页间让步及优先级公平保持，显式升序完整API用于兼容而不由展开动作触发。离屏停止排队自动读取和详情重试，保留断点、顺序及结束状态核对。

聊天历史在真实上行滚动、触摸或键盘操作到达顶部后自动读取一页更早消息，首次定位不触发，不因程序滚动连续拉全量。触发点为真正触顶而非提前80px，避免与仍在进行的上滑动画叠加。前插优先锚定原可见消息或折叠过程的相对位置，节点替换时按原轮次中的稳定item身份查回，缺少消息锚点时退回轮次或高度差；用instant补偿避免CSS平滑滚动导致跳动，仅在上下文、用户意图和位置仍一致时应用。过程分组补入旧条目时保留原展开锚点，拆分后仅原条目所在分组继承。触顶加载不清除进行中的触摸或滚动条跟踪，反向回底仍可恢复跟随。失败暂停自动读取，在顶部显示唯一重试入口。`codex-runtime-errors` 同时发布真实 `errorOwner`，不能用相同文案推断错误归属或隐藏独立操作错误。

聊天 GET 读取共用120秒总期限与30秒无进度期限，响应头和非空正文数据刷新无进度计时；认证恢复与重试沿用同一预算，取消后不发布迟到结果。写请求保持15秒期限及不确定回执核对。首次正文未返回时显示加载或失败重试，确认空历史后才显示空状态。实时连接建立超过30秒、出错但没有关闭事件时也会重试；手机回前台会恢复可能陈旧的连接，短暂切换保留节流与原 epoch/seq 追赶。

工作区变更面板只在轮次已结束且该轮有明确的文件路径记录时展示；进行中、未知状态或本轮无文件记录时均不挂载，也不为它读取Git。没有本轮记录时不能回退到整个工作区的未提交修改，旧轮次文件仅保留在其所属轮次。近视口才为已有本轮文件摘要检查工作区能力，离屏、后台、身份变化及卸载中止所属读取并拒绝迟到结果；不定时轮询、不自动下载全部diff。任何轮次仍在运行时，历史文件摘要保持可查看，共享工作区的读取与撤销暂缓。

`/api/workspace-changes?summary=1` 只读取Git状态和一次NUL分隔numstat，不生成逐文件diff；未知行数返回null与statsKnown:false。重复`path`参数允许按需读取最多50个当前变更文件的完整差异，作业身份包含摘要模式及路径集。文件展开后才取其diff；默认完整读取与已完成历史的写入校验保持兼容。MarkdownIt及图片、链接、表格规则仅在实际渲染Markdown时初始化，纯文本与代码高亮不创建解析器。已取得完整模型目录过期后立即以stale/refreshing返回，后台单飞刷新；首次无完整缓存仍等待真实结果，失败保留目录与错误，能力和默认值不伪造。

以下完整目录状态与4秒轮询规则用于旧兼容入口。

分组视图保留桌面分组和会话顺序，默认每组展示5条，展开状态不被轮询覆盖；最近活动视图按真实活动时间降序，按官方线程身份去重，并显示所属项目。视图选择保存在网页本地。列表轮询更新已确认运行标记，未知状态不冒充空闲。

`session-catalog-runtime` 负责目录读取、认证代次和共享配置请求，沿用 App 的同一份列表状态；历史/live 激活保留在 `session-runtime`。`session-list-sync` 独占4秒轮询及可见性监听：隐藏周期跳过读取，隐藏转可见立即通过原单飞同步；手动/初始化和在途读取不因此取消。停止清理原 window/document 上的计时器/监听，旧回调失效，SSR安全。

`sessionListReady` 表示已有可显示目录，`sessionListComplete` 独立表示全量就绪，首批的 `sessionListCounts` 保存真实总数。冷读显式选择渐进，暖完整目录继续普通 JSON。尾部失败保留首批/计数并允许重试；完整成功原子替换并清 counts，不能把部分数据当作完整搜索或空目录。`sidebarStatus.degraded` 同样通过唯一错误入口呈现：首次空降级不确认完整，非空可用 fallback 可带提示展示，已有完整列表保留身份；partial 后的合法非空 fallback 可推进完整，正常恢复清提示。认证失效清两阶段并取消所属读取，旧首帧/尾帧/错误/finally均无发布权。

默认 `stopSessionListSyncLoop()` 仍允许在途读取完成。App内部离开列表显式传 `{abortBootstrap:true}`，仅取消本次未完整的冷 GET，安静释放单飞及loading，保留可用首批供重进；不取消暖刷新、配置或任何模型/写动作。`session-list-progress` 派生局部展示完整性与真实计数：首批行可打开、组折叠和两视图保留，更多/新增在完整前禁用；查询可保留但等待完整数据，不给局部结果数或假无匹配。完整后恢复原全量预览搜索与操作，不新增第二份目录缓存。

输入设置、Git 与发送方式统一使用原生 `dialog.showModal()`，背景文档保持 inert，允许浏览器自身的 Tab 导航。Escape、图标和真实 backdrop 关闭后恢复入口；设置切 Git 先关后开。若运行结束导致原入口在 DOM 更新后移除或禁用，再受控检查输入框或稳定宿主；新弹层、已有效聚焦的元素、旧代次及卸载状态不得被该补查抢走焦点。

图片入口由 Renderer 选择按需挂载的 `ImageLightbox`，统一使用原生 dialog/top layer 与共享可视区域高度、顶部偏移。图片尺寸受同一高度约束，关闭按钮不被缩放图片覆盖；多触点数变化重建当前缩放和平移基线。图片层在自身处理 Tab/Escape，保护底层预览；焦点返回使用显式入口、连接/可用性与归属检查及 preventScroll，卸载不排队恢复旧焦点。该组件不接管其他弹层之间的全局键盘关系。

`PreviewHost` 只处理未被消费且没有当前原生 dialog 的键盘事件，避免背景预览取消 Escape 默认动作、关闭背景服务或拦截顶层 Tab。顶层设置关闭后，预览继续使用原 Escape 与窄屏 Tab 行为。当前原生 dialog 均通过 showModal 打开，沿用 `dialog[open]` 识别；若未来增加 show() 的非模态入口，需重新核对该边界。

窄屏打开的预览约束当前页面焦点：capture focusin 和断点变化后的 nextTick 均重新核对 open、compact、原生 dialog 与 document.hasFocus；仅在预览范围之外时 preventScroll 聚焦可见关闭入口。外部/body/null 的 Tab 回到首末边界，iframe 内焦点保持；桌面输入、其他原生弹层、浏览器失焦、关闭及卸载不被接管。新监听在卸载时按相同 capture 参数移除，不重建 iframe 或分配另一份预览状态。

会话搜索在当前目录的规范化索引中匹配标题、预览、项目、路径和身份，多词采用 AND；不新增请求或持久查询缓存。分组及原记录顺序保留，搜索展开与普通展开独立，初次最多 20 组、每组 5 条，最近活动初次 20 条，后续由用户分批展开。App 持有当前认证内唯一列表视图状态；返回列表保留查询、手动展开/折叠、普通和搜索分页，查询变化按原规则重置搜索分页，清空恢复普通展开。身份失效或重新登录重建该对象，旧实例回调只持有旧对象；这些临时状态不写入 localStorage。

列表根自身为滚动主体，并提供 main 语义、名称与原生键盘入口。`session-list-position` 在卸载前保存同一认证对象内的有限位置快照，以 session/group 身份和相对列表内容视口偏移恢复，缺项时按该元素真实范围钳制像素回退；捕获、范围、锚点与写入都使用同一元素。返回后等待内容提交并仅恢复一次；即时 route/auth 代次、模式/查询变化、用户滚动或按键、旧对象和卸载会取消待恢复动作，轮询与预览状态变化不能反复抢滚动。不使用 KeepAlive 或持久查询缓存。

预览位置书签与请求生命周期独立，捕获显式标记的 `[data-app-scroll]` 列表、消息和输入滚动区域，兼容原窗口书签。App 在即时 route/auth 变化及自身卸载时失效旧书签和排队恢复，保留跨页打开的面板、内容与原请求结算；关闭旧聊天预览不能覆盖当前列表位置。显式打开新文档时，空书签重新捕获当前页面；同页切目标/重试沿用原 opener。关闭回调同时校验位置代次和原 preview revision，只恢复仍连接的原滚动元素，并用 preventScroll 返回焦点。

运行状态优先采用网页执行服务已知的活动轮次；后台只读最新轮元数据提供额外状态证据，限制并发、按真实元数据签名缓存，不能回退到整段旧历史读取。元数据更新保留最多30秒已确认的运行证据，避免15秒列表刷新反复先发布未知；同一线程只保留一个状态读取并追赶新签名，过期或失败转未知，确认完成转空闲。官方独立app-server可能将桌面仍在执行的线程返回为notLoaded/interrupted且无完成时间，该情况结合有界日志尾部证据判断，不能凭进程存活认定运行。状态查询本身不得刷新活动排序时间。
